# 🔥 گرمابندی ساختمان — پلتفرم فروش کتاب

**نسخه فعلی: v1.2.1**

## 📝 تغییرات نسخه v1.2.1
- **انیمیشن کتاب روی موبایل/PWA دوباره فعال شد:** قبلاً در بلوک «بهینه‌سازی» با `.bk3d{animation:none!important}` روی همهٔ نمایشگرهای ≤۷۶۸px شناورشدنِ کتاب **خاموش** بود (ثابت و بی‌جان). حالا شناورِ سبک و GPU-دوست (فقط `transform`، بدون blur) روی موبایل و حالت PWA نصب‌شده اجرا می‌شود؛ کی‌فریم‌های `bfltMobile`/`bfltTiny` پررنگ‌تر شدند (بالا/پایینِ بیشتر + چرخشِ ملایم، چرخهٔ ۴ ثانیه‌ای). برای کاربرانی که `prefers-reduced-motion` دارند همچنان خاموش می‌ماند.
- **رفع سرریز نام کاربری روی موبایل:** نام در ناوبار (`.u-nm`) حالا `max-width` + `ellipsis` + `nowrap` دارد و `.u-pill` با `min-width:0`/`max-width:46vw` جمع می‌شود؛ روی صفحات کوچک (≤۴۳۰px) سقفِ نام ۹۶px است تا دکمهٔ تم/سبد را از قاب بیرون نزند. روی ۳۲۰px هم پایدار است.
- **سوییچ تم به دکمهٔ گردِ ساده برگشت:** به‌جای اسلایدر قبلی، یک **دکمهٔ دایره‌ای** با آیکنِ خورشید (روشن) / ماه (تاریک) که با **fade + چرخش** جابه‌جا می‌شود؛ حالت hover (هالهٔ طلایی)، فیدبکِ فشردن (scale .9)، و رینگِ `focus-visible`. روی **همهٔ صفحات عمومی و پنل ادمین** یکدست است. (یک باگ قدیمیِ ادمین هم رفع شد: `toggleAdmTheme` با `textContent=""` آیکن را بعد از اولین تعویض پاک می‌کرد — حالا کاملاً CSS-محور است.)
- **بومپ کش PWA → `tb-1.2.1`:** چون استایل‌ها/اسکریپت‌ها تغییر کرد، نسخهٔ Service Worker بالا رفت تا کاربرانِ نصب‌کردهٔ PWA دارایی‌های تازه را بدون رفرشِ سخت بگیرند.
- **تحلیل درآمد (مودال ادمین):** مسیر `/api/admin/revenue` در کد **موجود و درست** است — با اجرای محلیِ همان `server.js` روی یک دیتابیس درون‌حافظه، پاسخ **HTTP 200** با دادهٔ صحیح تأیید شد. خطای «مسیر یافت نشد» وقتی رخ می‌دهد که بک‌اندِ **در حال اجرا روی هاست نسخهٔ قدیمی** باشد (قبل از افزوده‌شدن این مسیر) یا اصلاً بالا نباشد (همان ۵۰۳). راه‌حل: استقرار کد فعلی + `npm install` + ری‌استارتِ Node.

## 📝 تغییرات نسخه v1.2.0
- **اسکنر QR (بازنویسی با html5-qrcode):** کتابخانهٔ قابل‌اعتماد `html5-qrcode` جایگزین شد (lazy-load هنگام باز شدن دوربین). پس از اسکن، شناسه استخراج و اگر به محصولی مربوط باشد **بلافاصله به صفحهٔ همان کتاب/فصل** هدایت می‌شود؛ در غیر این صورت در فروشگاه جستجو می‌شود.
- **مودال تحلیل درآمد (داشبورد ادمین):** کلیک روی ویجت «درآمد» مودالی با تفکیک **۷ روز اخیر / این ماه / امسال / امروز / کل** باز می‌کند. دکمهٔ **ریست درآمد** با تأیید «واقعا موافق هستید یا خیر؟» — درآمد انباشته صفر می‌شود **بدون حذف سفارش‌ها و خریدهای کاربران** (نقطهٔ صفرِ درآمد ذخیره می‌شود).
- **ویجت پرفروش‌ترین محصول** روی داشبورد (بر اساس مجموع فروش).
- **سوییچ تم روشن/تاریک:** آیکن خورشید + ماه با دستهٔ لغزان و انتقال نرم CSS؛ آیکن فعال طلایی می‌شود.

## 📝 تغییرات نسخه v1.1.2 — SEO

- صفحات خصوصی (داشبورد، پرداخت، ادمین، تعمیر، ۴۰۴) → `noindex, nofollow`.

- داده‌ساختاریافته JSON-LD (WebSite + Organization + SearchAction) روی صفحهٔ اصلی.
- شاپ حالا `?q=` را هم می‌خواند (برای جستجوی سایت‌لینک گوگل).
- **توجه مهم:** ایندکس‌شدن در گوگل فقط وقتی ممکن است که سایت **بالا (۲۰۰)** و روی **HTTPS** باشد و در **Google Search Console** ثبت + sitemap ارسال شود. (الان سایت ۵۰۳ و بدون https است.)

## 📝 تغییرات نسخه v1.1.1
- رفع خطای آپلود ۵۰۰ روی cPanel: فایل `manifest.webmanifest` به **`manifest.json`** تغییر کرد (هاست/mod_security پسوند `.webmanifest` را هنگام آپلود مسدود می‌کرد). همهٔ ارجاع‌ها، Service Worker و MIME سرور هم به‌روزرسانی شد. PWA بدون تغییر دیگری کار می‌کند.

## 📝 تغییرات نسخه v1.1.0 — PWA
- سایت حالا یک **PWA نصب‌شدنی** است: `manifest.webmanifest` (نام، آیکن‌های ۱۹۲/۵۱۲ و maskable، تم، حالت standalone، شورتکات‌ها)، متاتگ‌های نصب iOS/Android در همهٔ صفحات، و یک **Service Worker** (`/sw.js`).
- Service Worker با **کش نسخه‌دار** (`tb-1.1.0`): پوسته (HTML/CSS/JS/فونت/آیکن) پیش‌کش می‌شود؛ صفحات network-first (آنلاین تازه، آفلاین از کش)؛ assetهای ثابت stale-while-revalidate؛ مسیر `/api/*` هیچ‌وقت کش نمی‌شود. با هر بالا رفتن نسخه، کش قدیمی پاک و SW جدید فوری فعال می‌شود (skipWaiting + clients.claim + reload خودکار یک‌بار).
- آیکن‌های PWA از `favicon.svg` ساخته شدند: `assets/icon-192.png`، `icon-512.png`، `icon-maskable-512.png`.
- نکته: **PWA فقط روی HTTPS** نصب می‌شود (روی `garmabandi.ir` با SSL درست است؛ روی `localhost` هم کار می‌کند).

## 📝 تغییرات نسخه v1.0.9
- **رفع کامل دکمهٔ «بستن تیکت»:** باگ اصلی این بود که دکمهٔ بستن داخل گفتگو فقط وقتی وضعیت «پاسخ‌داده» بود نشان داده می‌شد؛ حالا برای **هر تیکتِ باز** (در انتظار/پاسخ‌داده/منتظر مشتری) همیشه هست. با زدن آن: وضعیت «بسته شده» می‌شود، گفتگو کاملاً قفل می‌شود (کادر پیام + دکمهٔ تصویر + ارسال غیرفعال، نشان «بسته شده»)، و سرور هم هر پیام جدید را با ۴۰۳ رد می‌کند.
- **انتشار آنی قفل به سمت کاربر:** گفتگوی باز هر دو طرف (کاربر و ادمین) هر ۶ ثانیه به‌روزرسانی می‌شود؛ به‌محض بستن توسط ادمین، **کادر کاربر هم خودکار ظرف چند ثانیه قفل می‌شود** (بدون نیاز به رفرش). این جریان به‌صورت دو-نشسته (کاربر + ادمین هم‌زمان) در مرورگر تست و تأیید شد.

## 📝 تغییرات نسخه v1.0.8
- **رفع باگ پنل ادمین (تست‌شده):** هنگام بستن تیکت از داخل گفتگو، کادر پاسخ حالا **فوری قفل** می‌شود (قبلاً فقط نشان وضعیت عوض می‌شد و کادر باز می‌ماند — `setAdminStatus` حالا کل گفتگو را دوباره رندر می‌کند). با یک سرور تستیِ درون‌حافظه‌ای، ۲۷ تست یکپارچهٔ بک‌اند (تیکت/وضعیت/پاسخ/قفل/بازگشایی/آمار/کاربران) و کل جریان UI ادمین در مرورگر تأیید شد.
- **دکمهٔ «بستن تیکت» روی هر کارت:** در فهرست تیکت‌های ادمین، هر کارت یک دکمهٔ بستن/بازگشایی جدا (با فاصله‌گذاری درست، بدون هم‌پوشانی) دارد؛ کلیک → وضعیت «بسته شده»، قفل کامل گفتگو و به‌روزرسانی آنی UI.
- **سرعت (واقعی):** کتابخانهٔ ۲۵۶ کیلوبایتی `jsQR` فقط هنگام **باز شدن دوربین** بارگذاری می‌شود (نه روی لود صفحهٔ QR)؛ کوتاه‌شدن اسپلش اولیه؛ lazy-load برای تصاویر چت؛ (قبلاً: حذف blur موبایل، توقف انیمیشن‌ها، throttle اسکرول، حذف محصولات تستی، gzip).

## 📝 تغییرات نسخه v1.0.7
- **بستن کامل تیکت:** وقتی ادمین تیکتی را می‌بندد، گفتگو کاملاً قفل می‌شود — نه کاربر و نه ادمین نمی‌توانند پیام جدید بفرستند (هم در UI با ورودیِ غیرفعال و نشانِ «بسته شده»، هم در سرور با خطای 403). برای پاسخ، ادمین باید ابتدا تیکت را بازگشایی کند.

## 🚀 نصب و راه‌اندازی

### پیش‌نیاز
**Node.js نسخه ۱۸ یا بالاتر** نصب باشد:
- دانلود: https://nodejs.org
- تأیید نصب: `node --version`

### مرحله ۱ — کپی تنظیمات
```bash
cd backend
cp .env.example .env
```
فایل `.env` را باز کنید و مقادیر را تغییر دهید.

### مرحله ۲ — نصب وابستگی‌ها
```bash
cd backend
npm install
```

### مرحله ۳ — اجرا
```bash
node server.js
```

سایت روی آدرس زیر آماده است:
**http://localhost:3001**

## 🔑 ساخت اکانت ادمین

۱. ابتدا با شماره موبایل خود در سایت ثبت‌نام کنید
۲. سپس در ترمینال این دستور را اجرا کنید:

```bash
curl -X POST http://localhost:3001/api/admin/make-admin \
  -H "Content-Type: application/json" \
  -d '{"phone":"09xxxxxxxxx","secret":"thermal2024admin"}'
```

*یا در PowerShell ویندوز:*
```powershell
Invoke-RestMethod -Uri "http://localhost:3001/api/admin/make-admin" `
  -Method POST -ContentType "application/json" `
  -Body '{"phone":"09xxxxxxxxx","secret":"thermal2024admin"}'
```

## 🛟 رفع مشکلات رایج

**خطا: `Cannot find module 'lowdb'`**
```bash
cd backend && npm install
```

**خطا: `EADDRINUSE: port 3001`**
```bash
# پورت را در .env تغییر دهید
PORT=3002
```

**خطا: `Cannot connect to API`**
مطمئن شوید سرور در حال اجرا است (`node server.js`) و به آدرس `http://localhost:3001` وصل هستید.

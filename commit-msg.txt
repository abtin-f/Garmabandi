Clear the admin badge on reject, fix the mobile order row, surface SMS config

1) The "1" badge on سفارشات never went away after rejecting a receipt.
   Two reasons: the badge was only ever .add("show"), never removed, and
   it counted failed+pending, so a rejected order kept it lit. A rejected
   order is finished work. refreshBadges() now counts only pending_review
   and toggles instead of adding, and every mutation calls it.

2) The order row broke on phones — the title column collapsed to a few
   pixels and wrapped one word per line. .pi-r is flex-shrink:0 and the
   card-to-card labels ("در انتظار بررسی فیش" + "قفل تا تأیید") are wide,
   so they ate the row. Under 640px the row is now a 2-column grid with
   the status pill and button on their own full-width row; under 380px
   those stack. Verified in a 390px iframe: .pi-inf gets 274 of 351px and
   the title renders on one line.

3) Order SMS never sent because the three template ids and
   ADMIN_ALERT_PHONE are still empty in .env on the host — notifySms
   returned silently, so there was no way to tell from outside. It now
   counts sent/failed/skipped with a reason, warns loudly at startup, and
   exposes GET /api/admin/sms-health listing exactly which vars are
   missing. The templates still have to be created in the sms.ir panel;
   /send/verify only accepts approved templates, not free text.
